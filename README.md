# 台詞小精靈（通用版）

上傳任意劇本（Word `.docx`、文字型 PDF、貼上文字），自動解析成結構化劇本，載入背誦介面（隱藏自己的台詞、朗讀對戲、測驗、接話、循環播放、成績）。
規格見 [SPEC.md](SPEC.md)。前端是單一 `index.html`；劇本只存在使用者自己的瀏覽器（IndexedDB）；解析時文字會送到 Cloudflare Worker → OpenRouter 的 LLM，LLM 只回標籤，台詞由本機依行號取回，所以不會改字、漏句、幻覺。

網址（GitHub Pages）：`https://cjlcv6061-svg.github.io/Script-wizard/`

## 使用流程

1. **首頁**：我的劇本（開啟／校正／重新命名／匯出／刪除）、「新增劇本」、「匯入 JSON」。
2. **新增**：選 docx／PDF／txt，或貼上文字（掃描 PDF 會提示不支援）。
3. **同意畫面**（首次）：說明文字會送到第三方 AI 服務。
4. **解析進度**：第一段歸納格式、第二段分塊標記；顯示塊數與失敗塊數；可取消。相同內容（SHA-256）直接用本機快取，不重複呼叫。
5. **預覽校正**：逐行列表，橘色邊框＝待人工校正（可一鍵跳下一個）；改標籤（台詞／指示／雜訊）、改角色（可合說）、改文字、與上一行合併、在游標處拆行、插入／移除場次分隔、角色重新命名／合併／設性別／刪除未使用角色。每次修改即時寫回 IndexedDB。
6. **選角**：依角色清單選要背的角色，進入背誦介面。

清除瀏覽器資料會讓劇本消失；換裝置或備份請用「匯出」（v2 JSON，可選含成績）。

## 開發與測試

```sh
npm install
npm test           # 語法檢查 + 單元／整合 + 與原 app 的迴歸比對 + 真瀏覽器端到端（需 Chromium、wrangler）
npm run fixtures   # 產生評測用的合成劇本與 docx/PDF（需要 python-docx、reportlab）
python3 -m http.server 8000   # 本機預覽 http://localhost:8000/
```

`npm test` 包含：與原 app 逐場逐角色比對渲染結果（1626 項完全一致）、解析管線（含重試／後備／fatal 中止）、Worker（CORS、上限、限流、請求內容、輸出過濾、日誌）、Chromium 手機尺寸的校正頁與離線、以及「真 Worker（workerd）＋ 假 OpenRouter」的 docx 上傳 → 解析 → 校正 → 背誦端到端。缺少 Chromium／wrangler 時，對應測試會自動略過。

## 站長待辦（Claude Code 無法代做）

2. **Cloudflare / OpenRouter / 部署 Worker**：照 [worker/README.md](worker/README.md)；`OPENROUTER_API_KEY` 只用 `wrangler secret put` 在終端機貼上。
3. **填 Worker 網址**：部署後把 `https://tsj-parse.<你的子網域>.workers.dev` 填進 `index.html` 的 `TSJ_CONFIG.WORKER_URL`（目前已填 `https://tsj-parse.scriptwizard.workers.dev`）。
4. **確認模型與供應商的資料政策**：目前部署設定是 `anthropic/claude-haiku-5.5`、`PROVIDERS="anthropic"`（`worker/wrangler.toml`；請求固定帶 `data_collection:"deny"`）。請到 OpenRouter 模型頁與官方條款確認該供應商不訓練、不保留提示詞，並依此修訂同意畫面的隱私聲明（現在的文字是 SPEC 第 9 節的草稿）。更換模型或供應商只改環境變數。
5. **用真實劇本評測**：真實模型（Haiku 5.5）已用 5 份真實檔案跑過（紀錄見 [eval/README.md](eval/README.md) 的「真實模型實測紀錄」），但**沒有人工標準答案**，數字只能當參考；`eval/real/` 在 repo 裡仍是空的（預設不 commit）。要有可信的準確率，請把真實劇本與人工校對過的標準答案放進 `eval/real/`，用上線相同的 `MODEL`、`PROVIDERS` 跑 `node eval/run.mjs --mode live --real eval/real --docs`；也可以用 `node eval/nonscript-sweep.mjs` 重新檢視「遠離劇本」門檻。
6. 待你決定：每 IP／全站每日上限初值（現為 100／600，見 `worker/wrangler.toml`）、角色顏色調色盤（現沿用原暖色系，`ROLE_PALETTE`）、深色模式（現沿用原 app：只有深色）。

## 與規格的差異與取捨

- **mammoth／pdf.js 放在 `vendor/`**，不走 CDN：離線可用、PWA 可快取、同源；pdf.js 以 `isEvalSupported:false` 載入。
- **第一段格式歸納**除了前 200 行，劇本更長時再取 5 個 40 行的中後段片段（總共 ≤ 400 行），讓只在後段登場的角色也進得了角色清單。
- **獨立成行的角色名**（置中式版面）標 `N`，其下一行才是 `S`；提示詞已寫明。
- **行首前綴由規則決定（前綴優先）**：劇本若大多數台詞以「兄：」「Madison – 」開頭（≥10 行且 ≥25% 的行），標記完成後會用前綴覆寫模型：有前綴的行一律是台詞、角色以前綴為準；沒有前綴卻被標成台詞的行改用本機規則標並標為待校正；一行裡夾著別人的前綴也標為待校正。模型沒列出、但前綴出現夠多次（≥5 次且占 5%）的稱呼會補進角色清單；模型在標記時用了清單外的角色、而該行行首真的寫著這個稱呼，也會採納（次要角色）。完成後整理角色清單：沒有任何台詞的角色（模型編的）不留，名稱在原文找不到（或只有單字，不算依據）就改回 id。模型標對的行完全不動。起因：模型常把有明確前綴的行標成續行或雜訊、把舞台指示標成台詞、編出不存在的角色與名字。
- **旁白、畫外音、合說（前綴格式的劇本，全由規則決定）**：行首的「旁白：」「VO：」「V.O.：」「O.S.：」「畫外音：」「Narrator:」「解說：」本身就是說話者（單獨出現一次也算，不問模型、不看次數）；「琳V.O.：」「良 O.S.：」「輝（畫外音）：」去掉畫外音標記後是已知角色就算那個角色在畫外說話；「輝，華：阿嫲！」逗號合說只有每個稱呼都是已知角色才算（句子裡的逗號太常見，不能一律當分隔）；縮寫合說「老人乙/丙：」＝老人乙＋老人丙（後面的稱呼借用第一個稱呼的開頭，找不到對應角色就不確定）；破折號貼著字的寫法（`Madison- So?`、`Alexandre –I don't…`）只在稱呼是已知角色、破折號至少一邊有空白時才算（`Madison-based` 不算）。
- **候選稱呼分類（前綴格式的劇本，多一次小請求）**：本機程式統計行首「稱呼：」出現的所有詞（出現 ≥2 次、模型第一段沒列出的），連同次數與一行例句做成一張小表，交給模型分類：R＝角色（含次要、群眾角色）、A＝某個已知角色的簡稱（`楊`＝`楊淑華`）、N＝不是角色（`SD Cue`、`歌曲三`、場次標記…）。Worker 新增 `mode:"roles"`（請求 `candidates:[[稱呼,次數,例句],…]` ≤150 個、`roles` 可省略；輸出只放行「稱呼|R／N／A|對應角色」格式的行）。起因：次要角色與簡稱不在第一段的角色表、又低於「補進角色」的出現次數門檻，標記時被標成雜訊而在畫面上消失，且多半沒有被標待校正。這一步是選擇性的：失敗、回不出可用的答案、Worker 還不認得這個模式（400）都只是略過，維持原本的結果。
- **劇本以外的內容（論文、附說明的劇本）**：劇本只是整份文件的一部分時，模型常把論述文字標成舞台指示、把引用的劇本片段標成台詞。標記完成後（`trimNonScript`）：
  - ①**人物表**（不受下面 ≥50 行的限制）——連續 ≥4 行「角色名：簡介」、每行行首名字都不同、內容是簡介（年齡、身分、與別人的關係，例如 `阿珍：（阿燈的老婆）年紀約75歲`；沒有「我」、沒有驚嘆號或問號）→ 改雜訊，連同簡介折行的續行。只出現在人物表的角色不留。自我介紹的台詞（有「我」）、只有 3 行、同一角色連續發言都不動。
  - 以下兩條在台詞＋歌詞 ≥50 行才跑：②**引文**——台詞行冒號後接引號（`阿燈:「阿珍，你知道…」`），而全劇這樣開頭的台詞不到 10%，且前後 4 行內沒有一般台詞（孤立）→ 改雜訊；③**遠離劇本**——指示／續行／標題行，前後 60 行內沒有任何台詞或歌詞 → 改雜訊（舞台指示一定夾在台詞之間；前言、大綱、論述離最近的台詞很遠）。60 行的取捨與掃描見 [eval/README.md](eval/README.md)：誤傷要兩側都離台詞 ≥60 行才會發生（獨白或舞台指示塊要 ≥119 行），代價是緊鄰劇本前後各 59 行的論述清不掉。
  - ④**幕尾標記**——`第二幕完`、`全劇完`、`劇終`、`THE END` 緊接劇本（60 行內）而被標成雜訊或標題時，改成指示（不切出叫「完」的場次，也不丟掉）；啟發式後備同樣不把它當標題。
  沒有論述的劇本不受影響。
- **指示括號與括號折行**：台詞裡的 `（…）`／`(…)` 一律當指示，從朗讀用的 `t` 移除、`r` 保留含指示的原文。**`【…】`** 只在整份劇本偵測到用它寫指示時才算（整行被 `【】` 包住、而且不是台詞／歌詞／標題的行 ≥3 行，且占 `（）`＋`【】` 整行的 25% 以上），偵測結果存在 `meta.dirPairs`（選用欄位，只認白名單 `["【】"]`），校正頁重建台詞時用同一組括號。偵測到時：台詞裡內嵌的 `【笑】`、整行 `【燈暗。】` 的處理與 `（）` 相同；歌曲提示也認得 `【唱《帝女花》】`，整行 `【眾人鼓掌】` 不會被吞進歌詞。
  指示寫到一半換行時（常被標成舞台指示、括號沒關上的半截會被朗讀）：前一行（台詞或續行）有沒關上的括號、而且往後看 6 行內括號真的關上 → 這幾行指示改成續行；反過來，一行以開括號開頭的整段指示自己沒關括號，後面被標成續行的半截改回指示（否則會併進上一句台詞）。括號一直沒關上的多半是打錯，不動；中間冒出別人的台詞、`:(` 表情符號都不動。
- **標點正規化**：中線省略號 `⋯`（U+22EF，有些字型把「……」存成這個字）在組回與校正頁重建台詞時換成 `…`（U+2026），套用在朗讀用的 `t`、指示 `d`、歌詞；`r` 與雜訊 `x` 保留原樣。朗讀與比對的標點表只認 `…`，不換的話 `⋯⋯` 會被當成要唸出來的字。粵拼字典補了口語句末助詞「㗎」（gaa3）。
- **PDF 版面：左欄說話者／右欄台詞、沒有冒號；每個字之間有空白**：①整份文件判斷名字欄（候選行的名字欄 x 在全文累計 ≥12 次且占候選 40% 以上；只看名字欄的 x，因為台詞欄 x 隨名字長短變動），名字後補「：」；單頁判斷會被長段台詞稀釋（名字行 <20%）而放棄。目錄的「第X場」不算名字。②整份文件「中日文字－空白－中日文字」超過一半時，去掉字間空白（英文字母之間保留）。③**帶頁碼的頁眉頁尾**：邊緣行（頁面頭尾各 3 行）有一個獨立整數、位在行首或行尾，而且「整數 − 頁序」是常數（同形狀、同位置、跨 ≥3 頁、至少 80% 吻合）→ 整行是頁眉頁尾（例如劇本合集每份劇本各自的偶數頁頁眉「12 陳麗芬 《廢胎》」，每種只出現約 10 次，達不到「出現在三成以上頁面」的門檻）。頁碼從頭重編的文件每一段各自成立；場次標題（第N場）、台詞形狀、含冒號的行不算，所以一頁一場且場次號等於頁序的劇本不會被誤刪。
- **歌曲區塊（音樂劇的歌詞）**：歌詞沒有「角色名：」前綴，模型常把它們標成續行、指示或雜訊，或有些行被誤當台詞。標記完成後由本機規則整段收成 `{song, lyrics}`（資料格式見 SPEC 第 4 節），背誦畫面當參考卡片顯示（不編句號、不朗讀、不隱藏、不出題），背誦畫面有「🎵 歌曲」頁（有歌的劇本才出現），全劇的歌詞集中列出，按「到這一場」跳到歌曲位置。校正頁有「歌曲」標籤，可改歌名與歌詞、「拆成一般行」，也能把一般行改成歌詞並併進相鄰的歌。規則：①種子＝歌手標記行（`(合)　…`、`合)　…`、`二　楊)　…`，標記後接 Tab 或兩個以上空白）或歌曲標題行（`歌曲三：…`、`間場歌曲：…`、`♪ …`）；②從種子往前後延伸到連續的短行（≤40 字），碰到台詞、標題、整行括號的舞台指示、音效提示（`SD Cue`、`SL`、`VO`…）就停，前一行是台詞時不吞它的續行；③標題取冒號後的字，緊接標題的作曲／版權行當雜訊保留；④沒有歌手標記也沒有標題的歌詞：前一行以音樂提示結尾（`（音樂再起。）`、`(眾人唱起)`；含「完／結束／停」的不算），接著至少兩行連續短行就是歌詞；整行括號、很短、沒有句號的回聲行（`(真真好識嘆)`）夾在歌詞中間也算歌詞；英文歌詞行長度以半個字元計；英文人名列表（演員表）、`全劇完`、`第一稿：…` 這類劇末標記不算；⑤歌詞行占全劇一半以上視為誤判、整批放棄。只動模型標成 C／D／N 的行，不動台詞與標題，所以不依賴模型是否認得歌詞。
- **塊內只有少數行有問題時，不整塊作廢**：回應裡缺漏或角色不明的行 ≤25%（≤5% 直接採用，否則重試一次取較好的）時，其餘行照用模型的標記，只有問題行改用本機規則標並標為待校正；重複行、標籤不在集合內才整塊視為失敗；模型多編的、不屬於這一塊的列直接忽略。
- **標記失敗的塊**：重試一次後仍失敗，改用本機啟發式規則先標，並標為「待人工校正」（規格只說標為待校正）。
- **限流用 Durable Object（SQLite 版）**，不用 KV：KV 免費方案每天只有 1,000 次寫入，不夠記 600 次請求的計數；DO 計數是原子的、免費方案可用。
- **資料格式**在 v2 上多了兩個選用欄位：`{x:"文字"}`（被標為雜訊的行，供校正頁還原；背誦時忽略）與 `rv:true`（待校正）。`scenes[].lines` 的 `s／t／r／d／seg` 與原格式相同。
- **日文語音標記**是本機規則：以《離地》既有標記校準，72 行中 59 行完全一致；差異主要在歌詞行與粵語／日文交界（例如「我連こんにちは」）。需要時可在校正頁直接編輯 `⟦…⟧`。
- 第一版不做：登入、雲端存檔、OCR、專屬分享連結、瀏覽器內本機模型。劇本語言先固定當粵語朗讀（`meta.lang` 已存，尚未用來切換語音）。
- PDF：支援橫排與直排（欄由右到左；兩頁拼一張的版面依右到左讀）、不內嵌字型的繁中 PDF（靠 `vendor/cmaps/`）。雙欄橫排 PDF 的閱讀順序可能錯亂，請改用 Word 或貼上文字。圖片 PDF（掃描檔）仍不支援。
