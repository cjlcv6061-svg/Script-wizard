# 評測（SPEC 第 10 節）

## 資料

| 來源 | 內容 |
|---|---|
| `fixtures/ld.v1.json` | 《離地，到着》v1 劇本（22 場）。**免費金標準**：可反向生成原始文字 |
| `synth.js` | 由上面反向生成 7 種排版（冒號式、全形冒號、全名＋半形冒號、角色名置中獨立行、折行續行、空行分隔、封面／目錄／頁碼雜訊），附逐行標準答案 |
| `build_docs.py` | 把合成劇本輸出成 docx 與 PDF（頁眉、頁尾、頁碼畫在頁面邊緣，奇偶頁不同頁眉）；另有不內嵌字型的繁中 PDF（橫排／直排），以及書籍式雙欄 PDF `pdf-2col`（欄內「名字｜台詞」兩個儲存格、沒有冒號，奇數頁頁尾靠右、偶數頁頁尾靠左；塞不進欄寬的行略過，標準答案帶 `partial`，只評行級、不評端到端） |

```sh
npm run fixtures                 # 產生 eval/out/synth 與 eval/out/docs（需要 python-docx、reportlab）
```

## 執行

```sh
node eval/run.mjs --mode heuristic --docs     # 不用模型：本機啟發式基準線（不需要 key）
node eval/run.mjs --mode mock --err 0.02      # 模擬模型：驗證管線、重試與後備（不代表真實準確率）
OPENROUTER_API_KEY=... MODEL=<模型ID> node eval/run.mjs --mode live --docs   # 真實模型
```

- `--variants colon-fw,noisy` 只跑部分版面；`--real eval/real` 加入真實劇本；`--no-cache` 不使用回應快取。
- live 模式用與 Worker **同一份**提示詞與請求組裝（`worker/prompts.mjs`）、同一份解析管線（抽自 `index.html` 的 PARSER-CORE），
  所以評測的就是上線的東西。**必須用與正式上線相同的「模型＋供應商允許清單」**（`MODEL`、`PROVIDERS`）。
- 回應快取在 `eval/out/cache/`（以請求內容的 SHA-256 為鍵）：同樣的請求不重複計費，可離線重跑。
- API key 只從環境變數讀，不寫入任何檔案。

## 指標

- **行級準確率**：標籤（S/C/D/H/N）與角色皆對才算對；docx、PDF、純文字分開統計。前處理已移除的頁眉頁尾（答案為 N）算對。
- 另列各標籤召回、混淆矩陣、錯誤行清單（`eval/out/report.{json,md}`）。
- **端到端還原度**：組回後的劇本與原劇本逐行（角色＋台詞）相同的比例。
- 假設：小模型 ≥95%，剩餘錯誤集中在舞台指示與多角色合說行；低於 95% 才升級模型。

## 目前結果

### 合成劇本（本 repo 內可重跑；沒有真實模型的 key 也能跑）

合成劇本是規律排版，**比真實劇本乾淨很多**，高分不代表真實劇本也能高分，真實準確率要用 `real/` 與 live 模式量。

| 模式 | 說明 | 結果 |
|---|---|---|
| heuristic | 本機規則，角色清單由答案給定 | 純文字 99.2%、docx 99.7%、PDF 97.0%（最差：雜訊版 N 召回 39%，頁碼以外的雜訊要靠 LLM） |
| mock（完美） | 模型標籤＝答案 | 12 份全部 100%，組回與原劇本逐行相同（PDF 99.6%，差在測試字型缺字的替換） |
| mock（err 2%、壞回應 30%） | 驗證重試與後備 | 97.9–98.4%，失敗塊自動改用本機規則並標為待校正 |

  多出的 278 行雜訊（原標籤：指示 253、續行 10、標題 8、台詞 7）是六份劇本各一段的封面標籤／劇名／署名、作者簡介、編劇的話、角色表、分場表；

## 「遠離劇本」門檻（`trimNonScript` 的 `NONSCRIPT_FAR`，預設 60）

```sh
node eval/nonscript-sweep.mjs --docs      # 掃描各門檻；--docs 另加 eval/out/docs 的 docx／PDF 標準答案
```

規則：指示／續行／標題行，前後 FAR 行內都沒有台詞或歌詞 → 改雜訊。兩種風險方向相反：

- **誤傷**：真實劇本裡的指示／續行被清掉。兩段台詞之間的內容（長獨白的折行續行、長舞台指示塊）要**兩側都**離台詞 ≥FAR 行才會被清，
  所以安全長度是 2×FAR−1 行（FAR=60 → 118 行）。
- **殘留**：劇本前後的前言／論述，緊鄰劇本的 FAR−1 行清不掉（FAR=60 → 每側 59 行）。

用標準答案的標籤餵給 `trimNonScript`（《離地》的 7 種合成排版＋docx／PDF 共 15 份；唯一的真實劇本，換不同排版）：

| FAR | 誤傷（真實的指示／續行被清掉的行） | 最小會被清的獨白／指示塊 | 300 行前言的殘留 |
|---|---|---|---|
| 10 | 83 | 19 行 | 9 行 |
| 20 | 0 | 39 行 | 19 行 |
| 30 | 0 | 59 行 | 29 行 |
| 40 | 0 | 79 行 | 39 行 |
| **60（預設）** | **0** | **119 行** | **59 行** |
| 90 | 0 | 179 行 | 89 行 |
| 120 | 0 | 239 行 | 119 行 |

真實劇本裡指示／續行離最近台詞的距離：純文字排版最遠 4 行；折行的 PDF 排版最遠 17 行（長獨白折成多行，中間的續行離兩側的台詞最遠）。
所以 FAR≥20 在手上這份劇本上都零誤傷，FAR=10 開始誤傷折行的獨白。

**結論：維持 60。** 沒有證據支持改動：往下調（例如 30～40）只換來每側少殘留 20～30 行論述，代價是長獨白／長舞台指示塊的容忍長度從 118 行降到 58～78 行，
而這個容忍長度只在一份劇本上量過；折行 PDF 的實體行數是 docx 段落數的好幾倍（一段 12 行的英文舞台指示在 PDF 裡可能是 40 行）。
手上有更多真實劇本時，用 `--real` 的標準答案再跑一次掃描：若各份的最大距離都明顯小於 20，才有理由調到 30～40。
若只想更積極清掉論述，比起整體調低，更安全的方向是只收緊「第一句台詞之前／最後一句台詞之後」的邊緣（那裡的合法內容通常只有封面、人物表、開場與收場的短指示），
內部（兩段台詞之間）維持 60；這需要論文類的真實檔案來校準，尚未實作。
